Reviewed `design.md` at `92ecf063b` against the current decision log and `v2-cost-model.md`. Findings are numbered; "§" refers to design sections.

1. **blocker, §22 Wire / §30 "relay: header only, body forwarded opaquely" vs. §22 "one encoding per frame and link".** In p3 the only relay hop is IPC (structured clone) → WebSocket (binary envelope). A structured-clone body is not wire bytes, so the server must encode it; and a worker commit frame carries batches for several destinations (N client links plus the server's own holds), so the relay must split the body per link to keep "one state frame per commit per link". Neither the encoding point nor the split is defined, and "no decode, no walk, no re-encode" is impossible as written. Proposal: the origin encodes each hold's batch as its own byte segment (portable envelope, compressed above the threshold at the origin), IPC carries the segments as bytes, the packet header lists `(holdId → segment offsets)`; the relay slices and concatenates segments per destination link without parsing them, and only a local consumer decodes. State that compression is decided at the origin, not per link.

2. **blocker, §27 `accepts` value adapters + §5 "never with a schema a peer sent".** During a rollout a guest tab on R−1 calls `add(argsV1)`. The provider owns only the V2 schema; the V1 schema exists only in the peer's description, which must not be executed. So `methods: { add: (argsV1) => argsV2 }` receives unvalidated, unstripped guest input, and the mapped output is code output (not re-validated). Every rollout window opens an unvalidated path for guests. Proposal: `accepts[v]` carries the provider's own copy of the old member schemas (`{ args: OldArgs, state: …, methods: … }`); the provider validates old args against that copy before mapping, then validates the mapped args against the current schema (both compiled once).

3. **major, §9 "only `tx.draft`" vs. §9 "a transaction may just read several documents consistently and return a value" (and §9 "values read in a transaction are shared").** Drafts are Delta overlays that throw after `prepare()` ("draft handles are unusable from here on"). `read: ctx => self.tx(ctx, async tx => (await tx.draft(doc)).entries)` returns a dead proxy: a same-host caller gets throws, a remote caller's result is serialized after the tx closed and the encoder throws. The first proof hits this immediately (the approval store reading a pending question back). Only primitives can be returned today. Proposal: `tx.read(handle, key?)` returning the committed immutable revision (no overlay, no copy; the draft's current revision if drafted in this tx via Delta's materialize-on-demand), and a rule: never return draft subtrees.

4. **major, §9 `tx.draft` over `initial()` for absent documents.** Inside a transaction there is no way to tell "absent" from "equals `initial()`"; `remove` in the playground (`if (!(await tx.get(docs, id))) return false`) cannot be written, nor idempotent "create if missing with tags" vs. "update". Proposal: `tx.draft` returns `{ draft, exists }`-style information or `tx.exists(handle, key)` (metadata lookup, O(1) once loaded).

5. **major, §13 close may drain vs. §21 restart order (close, factory, reopen) vs. D2 "a pinned call starts on the new sandbox".** Code mode reload: the old sandbox's `close` drains running scripts (minutes); §21 restarts by closing first, so the new sandbox and the tool contribution (§17: "in the table from live until it … restarts") do not exist until the drain ends; a Durable task released from an approval hook finds no tool entry and no sandbox. Also undefined: how the old entry's `execute()` finds "the current sandbox" (the old attempt's `self.open` handle never changes; a module variable is forbidden), and what it does while the registry is momentarily empty. Proposal: on reload Chord opens the new attempt first and lets the old `close` drain in the background bounded by `closeTimeout`; the sandbox is a registry value (`codemode.sandbox`) the object contributes, swapped atomically at the new attempt's `live`; `host.registry(R).when(pred, signal)` with the park deadline for readers that must wait.

6. **major, §24 start barrier "open without scheduling, wait for the required contributions".** The harness waits inside its opener for `HarnessModels`; if the models plugin is missing or its native fails (`broken`), the harness never goes live, the start barrier never completes, holds park 60 s and fail `unavailable` with no reason, and keep-alive (no viewers, no tasks) stops the worker 5 minutes later; the operator sees nothing. Proposal: the harness opens unconditionally and publishes `{ kind: "waiting", missing: [...] }` state; a routine on the registries resumes scheduling when the required contributions appear; the start barrier counts it as live.

7. **major, §5 validation by trust: stripping and normalization for host principals are unspecified.** "Not validated in production" for server/worker code also skips stripping ("a handler receives exactly its declared shape") and, if read literally, input normalization. Scenarios: (a) a worker routine calls `catalog.update({ title, archived })` where the handler does `Object.assign(draft, args)`; the trusted path mass-assigns while the guest path cannot, so behaviour differs by caller; (b) an unnormalized input (defaults omitted) from a worker yields a second object identity for the same logical input. Proposal: always normalize inputs (identity) and strip args to the provider schema (O(args), args are small by design); skip only the schema check for host principals.

8. **major, §10 "checkpoints optional, no default; replay only when loading" + memory storage "stores ops".** A status/usage singleton written every second for a day accumulates ~86k deltas; the next worker start replays them all (and the SQLite file and the memory storage grow without bound; keyed docs evicted after 10 min replay their whole tail on every re-access). K9 moved the quadratic cost from commit to load, it did not remove it. Proposal: a store-level default (`deltasSinceBase > 64` or delta bytes > 2× base) that a definition can override, applied in the store, not the storage.

9. **major, §3 flow control "the window applies to every frame, first snapshots included" + "a relay whose window overflows releases the hold and re-holds; the provider sends a fresh snapshot".** A 500 KB state and a 256 KB window: the re-hold snapshot alone exceeds the window, so either it can never be sent (deadlock) or it is sent and immediately overflows again (re-hold storm, one full encode per cycle). Proposal: overflow is decided on queued deltas only; a snapshot is always admitted (it consumes credits); after an overflow the hold is marked "snapshot pending" and re-held only once credits cover the last snapshot's size, with a minimum interval.

10. **major, §15 D4 "a running job counts as a reference; a run ignoring the signal keeps its slot" vs. §4 revocation and §21 native restart.** A revoked guest's view object with a job that ignores the signal stays alive indefinitely after `revoke`; its job can keep calling out. The job's `ctx.principal` is undefined in the design. Proposal: jobs run as the host principal with attribution as data (state it); revocation and native restart abort the object's jobs and end the object when they settle or at `closeTimeout`, reported as a leak.

11. **major, §9 versions "the migrated base is persisted" + D9 "values are not walked".** `migrate` output and `initial()` are never checked in production. A buggy `migrate` (the one time a whole document is rewritten) stamps corrupt data with the new fingerprint, permanently. Proposal: validate `migrate` output and `initial()` against the schema always (once per document per bump, off the hot path); keep D9 for everything else.

12. **major, §25 "ignores reports from an older worker incarnation".** The server object receives the report as a method call from the worker principal; the principal carries no incarnation, and the host API exposes no way for server app code to learn the current child incarnation per address. Proposal: the worker sends `host.incarnation` as data, and `route`/the host exposes `host.children` (address → incarnation, live) or a `resolved` event so the receiver can compare.

13. **minor, §5 description once per (link, fingerprint).** As written every first hold of a type per link costs a round trip (hold → describe request → description → bind). The consumer knows whether it already sent that fingerprint on this link. Proposal: the consumer includes the description with the first hold of a fingerprint per link; the provider still asks if its cache misses (reconnect races).

14. **minor, §17 runtime composition.** Undefined: which objects may contribute. A `lifetime: "referenced"` object's contribution flickers with its viewers; a per-principal `remote` object would add one entry per guest. Proposal: contributions only from facets and `lifetime: "host"` objects (type-checked), or state the flicker explicitly.

15. **minor, §22 "no frame is walked" / §30 receive "header check".** Overbroad: the frame grammar (ids, `kind`, `args.kind`, batch shapes) still needs a structural check on untrusted links, and `state`/`view`/`result` frames must be refused by kind on accepted (client) links. Define: grammar check O(frame structure) with `Unknown` leaves (TypeBox Check as today), no `isValue` walk, kind allow-list per link kind; bytes recognized by `instanceof Uint8Array` (Node `Buffer` arrives as a subclass over IPC).

16. **minor, §29 telemetry across relays.** Relays "add a `chord.relay` span" and providers extract carriers, but relays do not decode bodies (1). Proposal: the carrier lives in the packet header next to the route; cap carrier size for frames from accepted links.

17. **minor, §6 dependencies after `live` (K3).** The design still describes dependency waiting only before `live`; what happens when a declared reference fails or is released after `live` (dependent stays live with stale values, or goes `loading`/`failed`) is not written. Proposal: a declared reference that leaves `live` marks the dependent `loading` (calls park) and fails it `transient` after `readyTimeout`, matching activation.

18. **minor, §3/§9 immutability by convention.** Concrete failure: a routine does `sessions[id].archived = true` on a value it received from `catalog.sessions`; the tracker's authority is mutated without ops, the next delta is computed against an assumed-unchanged revision, and every remote replica diverges permanently with no error (dev catches it only if that path runs under `dev`). Proposal: production freezes only the root object of every committed revision and every published value (`Object.freeze(root)`, O(1), catches `value.x =` and `Object.assign(value, …)`), deep freeze stays dev-only.

19. **minor, drift.** §5/§22 frame list lacks the description-request frame; the log's cost-guard bench still names JSONL though cut; §9 "values read in a transaction are shared" predates `tx.get` removal; the keep-alive counters ("Chord's counters") have no named API in §3/§19.
