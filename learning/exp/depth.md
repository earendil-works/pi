# 章节深度如何验收

上一轮以“15章、32图、48题”判断完成，数量齐备掩盖了内容仍是导读。用户指出压缩缺少细节后，重新以能否独立推导来验收。

参考站点 [Pi Agent 双轨教程](https://dg-ai-notes.pages.dev/) 的教学组织，学习其从问题展开机制的节奏。技术依据仍采用本地固定提交。外部文章里的字段、触发时机和错误策略必须逐项对照，不能根据相近文件名搬用。

## 每章必须交付的推理材料

用户明确要求整章重写时，应先重建该章的问题与解释顺序，再写完整正文。给已有短章追加机制段落，不能作为全章重写验收。逐章对应的推演与复核见[本轮记录](rewrite-audit.md)。

- 一个有具体数据和编号的场景，输出可以验算。
- 关键状态的所有者、读写入口和更新时序。
- 主要算法的执行步骤，说明分支选择和边界值。
- 从设计问题推出机制必要性，再说明成本与适用条件。
- 至少一种失败、取消、恢复或并发变式，以及正确答案。
- 源码导航连接到决定行为的代码，代码块之后解释它为何在此处执行。

篇幅不能代替以上材料。出现“预算超了就压”“工具并行就快”“写检查点就恢复”这样的概括，必须继续问它使用哪份输入、何时失效、从哪里切、什么先持久化、失败后由谁继续。

## 压缩章的深度基准

计量要讲有效usage与编辑后的失效；触发要分手动、阈值、overflow；切点要算反向累计并尊重工具配对；准备要拆历史与长段前缀；生成要讲材料序列化、工具结果字符限制和旧摘要更新；验收要讲默认生成与扩展接管的差别；恢复要讲先省略失败尝试再压缩，以及继续与停止条件。

新增图应补未解释的关系，而非为了视觉饱满重复主链。本轮新增预算切点和三条继续策略两图，全书预算相应调整为34张。

## 版本差异的处理

外部材料适合作为写法参考。若其案例使用当前版本已替换的钩子，或声称截断响应可执行工具、压缩仅在agent_end以后发生，应回本地实现重新描述。引用外部文章的教学组织不等于采纳其中所有技术结论。
