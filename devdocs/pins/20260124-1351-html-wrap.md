# Pin: Auto-wrap pasted HTML/XML in coding-agent TUI

## Goal
When a user submits HTML/XML (e.g. `<div>...</div>`) in the coding-agent TUI editor, it should remain visible as literal text in the chat view (not be treated as markdown/HTML and effectively “rendered away”). Today, wrapping in triple backticks works around it.

## Ground truth found (verified)
- User messages are rendered with the **pi-tui `Markdown` component**.
- `Markdown` uses `marked.lexer()` and **skips tokens of type `html`** (top-level / block HTML).
- Many HTML snippets (e.g. `<div>hi</div>`, `<p>..</p>`, `<img .../>`, `<!-- -->`) are parsed by `marked` as **top-level `html` tokens**, so they are omitted from terminal output.
- Wrapping the same content in fenced code blocks (``` … ```) produces a `code` token and is rendered correctly.

## Key files (current behavior)
- `packages/coding-agent/src/tui/user-message.ts` — renders user messages via `new Markdown(content, ...)`
- `packages/coding-agent/src/tui/tui-renderer.ts` — extracts text blocks, creates `UserMessageComponent`
- `packages/tui/src/components/markdown.ts` — `case "html": // Skip HTML for terminal output`

## Implemented
- coding-agent: user submissions that contain markdown HTML tokens are auto-wrapped in a fenced code block before being sent (and thus displayed).
- pi-tui Markdown: added opt-in `renderHtml` option to render `marked` HTML tokens as literal text instead of dropping them.
- coding-agent: assistant messages enable `renderHtml` so assistant HTML/XML output never disappears.

## Current state
Feature is implemented and verified via package tests and `npm run check`.

## Verification commands run
- `node --input-type=module` to inspect `marked.lexer()` output for HTML samples
- `node --input-type=module` to instantiate `Markdown` and confirm `<div>` disappears unless fenced
- `npm test -w @kennyfrc/pi-tui`
- `npm test -w @kennyfrc/pi-coding-agent`
- `npm run check`
