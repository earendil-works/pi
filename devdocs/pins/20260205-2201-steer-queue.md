# Pin: steer queue mode + queueMessageByAgentEnd/queueMessageNext

## Goal
Add a new `/queue` mode `steer` that sends the user’s message next (immediately after the current agent run completes), without interrupting the in-flight assistant message/tool work.

Additionally refactor the Agent queue API:
- rename `queueMessage()` → `queueMessageByAgentEnd()`
- add `queueMessageNext()` (priority enqueue)

## Constraints / decisions
- In `steer` mode we do **not** abort the current run; steering means “process next after agent_end”.
- Keep existing queued messages.
- Priority ordering should be FIFO among `queueMessageNext()` calls.
