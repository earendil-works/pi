# Pin: Moonshot (Kimi k2.5) support

## Goal
Add first-class **Moonshot** provider support for **kimi-k2.5** (OpenAI-compatible `/v1/chat/completions`) with correct handling of:

- Multimodal input (text + image)
- Thinking / reasoning traces preserved and sent back to the model (via `reasoning_content`)
- Moonshot request-shape quirks (e.g. `max_tokens` field)

## Constraints / Non-goals
- Keep changes tight; no refactors.
- Don’t add video support (the library only supports image attachments today).
- Must run `npm run check` at repo root before finishing.
- No commits.

## Current State
- Built-in models include Kimi via OpenRouter/Groq.
- No built-in `moonshot` provider.
- OpenAI-compatible adapter can parse `reasoning_content` / `reasoning` into internal `thinking` blocks.

## Progress
- Slice 1 complete: `moonshot/kimi-k2.5` is now generated into `@kennyfrc/pi-ai` model registry with:
  - `reasoningFormat: "reasoning_content"`
  - `extraBody.thinking: { type: "enabled" }`
  - `MOONSHOT_API_KEY` env var support
- Slice 2 complete: OpenAI-compatible adapter special-cases `api.moonshot.ai` to:
  - use `max_tokens`
  - avoid `stream_options` and `reasoning_effort`
  - verified via a mocked OpenAI SDK vitest

- Follow-up fix: model selector de-duplicates built-in vs `~/.pi/agent/models.json` entries by `(provider,id)` so `moonshot/kimi-k2.5` shows only once.
