## Goal
Update the `claudesync` bash function (defined in `~/.bashrc`) to support the new `~/.pi/agent/oauth.json` `accounts` format (nested credentials per account + `activeAccountId`).

## Constraints / Notes
- Do not print OAuth tokens.
- Preserve/maintain backwards compatibility with legacy top-level `.anthropic.access|refresh|expires|scopes` fields where possible.
- Keep oauth.json permissions restrictive (expect 0600).

## Current State
- `oauth.json` now stores Anthropic OAuth under `.anthropic.accounts[].credentials` and selects via `.anthropic.activeAccountId`.
- Existing `claudesync` reads/writes legacy `.anthropic.refresh/access/...` only.

## Next Step
- Patch `claudesync` to:
  - Read refresh token from the active account (fallback to legacy fields)
  - Refresh tokens and write back into the active account credentials
  - Update legacy top-level fields for compatibility
  - Keep file permissions at 0600

## Verification
- Run: `bash -lc 'source ~/.bashrc; claudesync'`
- Then sanity-check (no token output):
  - `jq -r '.anthropic.activeAccountId' ~/.pi/agent/oauth.json`
  - `jq -r --arg id "$(jq -r '.anthropic.activeAccountId' ~/.pi/agent/oauth.json)" '.anthropic.accounts[]|select(.id==$id)|.credentials.expires' ~/.pi/agent/oauth.json`

## Status
- `claudesync` updated to support accounts format.
- If you are seeing `403 ... OAuth token has been revoked`, the refresh token is also returning `invalid_grant` from the Anthropic token endpoint, which means you must re-authenticate (pi `/login` or `claude login`).
