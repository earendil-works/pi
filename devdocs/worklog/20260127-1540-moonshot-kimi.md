# Worklog: Moonshot (Kimi k2.5) support

## 2026-01-27
- Created pin for adding Moonshot provider + kimi-k2.5 model support.
- Slice 1:
  - Added `moonshot` to `KnownProvider` and `MOONSHOT_API_KEY` env mapping.
  - Extended model generator to emit optional `reasoningFormat`, `headers`, and `extraBody` fields.
  - Added built-in model `moonshot/kimi-k2.5` (vision + reasoning traces via `reasoning_content`).
  - Verified by building `@kennyfrc/pi-ai` and checking `getModel('moonshot','kimi-k2.5')` in `dist`.

- Slice 2:
  - Updated OpenAI-completions compat auto-detection for `api.moonshot.ai`:
    - `maxTokensField: "max_tokens"`
    - `supportsStreamOptions: false`
    - `supportsReasoningEffort: false`
  - Added `packages/ai/test/moonshot-compat.test.ts` (mocks OpenAI SDK) to assert request shape + reasoning_content passthrough.
  - Verified via `npm test -w @kennyfrc/pi-ai`.

- Slice 3:
  - Updated docs to mention `MOONSHOT_API_KEY`.
  - Added coding-agent default model mapping for `moonshot`.
  - Verified via repo root `npm run check`.

- Also updated local user config `~/.pi/agent/models.json` to include `moonshot/kimi-k2.5` using `MOONSHOT_API_KEY`.

## Follow-up: duplicate model entries in selector
- Root cause: `loadAndMergeModels()` appended custom models after built-ins without de-duplicating, so adding `moonshot/kimi-k2.5` to `~/.pi/agent/models.json` caused it to appear twice.
- Fix: de-duplicate by `(provider,id)` when merging; custom entries override built-ins.
- Added test: `packages/coding-agent/test/model-selector-dedup.test.ts`.
- Verified: `npm test -w @kennyfrc/pi-coding-agent`, `npm run check`.
