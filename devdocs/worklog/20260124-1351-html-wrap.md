# Worklog: 20260124-1351-html-wrap

## What I investigated
- Readmes for repo + relevant packages.
- Located how user messages are rendered in the coding-agent TUI.
- Traced the rendering pipeline into pi-tui’s Markdown component.

## Verified findings
- `packages/coding-agent/src/tui/user-message.ts` uses `new Markdown(content, ...)` to render user messages.
- `packages/tui/src/components/markdown.ts` uses `marked.lexer()` and drops top-level `html` tokens.
- `marked.lexer('<div>hi</div>')` returns a top-level `{ type: 'html', ... }` token.
- Rendering `<div>hi</div>` through `Markdown.render()` yields only blank/padding lines.
- Rendering ```\n<div>hi</div>\n``` yields a visible code block with `<div>hi</div>`.

## Commands run (high signal)

- `node --input-type=module` snippets to:
  - print `marked.lexer()` tokens for HTML/XML examples
  - render Markdown output lines for raw vs fenced HTML

## Changes made

### pi-tui
- `packages/tui/src/components/markdown.ts`: add `MarkdownOptions.renderHtml` (opt-in) and render HTML tokens as literal text when enabled.
- `packages/tui/src/markdown-html.ts`: add `containsMarkdownHtmlTokens()` helper (based on `marked.lexer()` recursion).
- `packages/tui/src/index.ts`: export `MarkdownOptions` and `containsMarkdownHtmlTokens`.
- `packages/tui/test/markdown.test.ts`: add tests covering default HTML drop + opt-in render.

### coding-agent
- `packages/coding-agent/src/utils/auto-fence-html.ts`: auto-fence entire message when `containsMarkdownHtmlTokens()` is true; chooses a fence longer than any backtick run in content.
- `packages/coding-agent/src/tui/tui-renderer.ts`: send fenced text to agent, keep raw text for prompt history + queue editing/preview; queue matching uses sent form.
- `packages/coding-agent/src/tui/assistant-message.ts`: enable `renderHtml: true` so assistant HTML/XML blocks do not disappear.
- `packages/coding-agent/test/auto-fence-html.test.ts`: unit tests for fencing behavior.
